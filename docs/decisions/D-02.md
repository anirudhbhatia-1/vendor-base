# D-02 — Primary clients and delivery sequence

**Status:** APPROVED — INTERNAL DEVELOPMENT ONLY  
**Accountable owner:** Engineering Lead  
**Due date:** 21 August 2026  
**Blocks:** No internal-development work; production release remains separately gated  
**Last reviewed:** 13 August 2026

## Context

The marketplace needs both an installable web experience and an Android application. The project owner chose to build both clients during the same company-development phase. This is a deliberate delivery-cost trade-off, not permission to publish either client.

## Approved decision

- Build a TypeScript PWA with Next.js.
- Build a TypeScript Android application with Expo and React Native.
- Develop both clients simultaneously against the same versioned HTTP contracts.
- Share contracts, validation schemas, translation keys, state and error names, synthetic-data builders, and basic design tokens.
- Keep screens, navigation, offline behaviour, device integration, and accessibility implementations platform-specific.
- Keep permissions, prices, availability, and workflow transitions authoritative on the server.

## Reasons

- Both client surfaces are required for company validation.
- Shared contracts reduce semantic drift without forcing inappropriate screen-level code sharing.
- Independent platform implementations preserve browser and Android usability, accessibility, offline, and device behaviour.

## Consequences

- Phase 2 must scaffold both clients and their shared contract packages.
- Client work must be planned as parallel product slices, so neither client silently becomes the only supported surface.
- Playwright will test PWA journeys and local Maestro will test Android journeys.
- Store publication, hosted PWA release, signing, production credentials, analytics, and external beta distribution remain out of scope.
