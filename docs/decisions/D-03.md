# D-03 — Internal development technology foundation

**Status:** APPROVED — INTERNAL DEVELOPMENT STACK ONLY  
**Accountable owner:** Engineering Lead  
**Due date:** 28 August 2026  
**Blocks:** No local foundation work; hosting, shared environments, recovery, and production release remain blocked  
**Last reviewed:** 13 August 2026

## Context

The company needs a free, reproducible local foundation before application construction begins. Hosting is intentionally deferred. Local completion must never be described as production readiness.

## Approved decision

- Use a pnpm workspace monorepo on Node.js 24 LTS with one committed lockfile and explicit `workspace:` links.
- Use Next.js with TypeScript for the PWA.
- Use Expo and React Native with TypeScript for the Android application.
- Use NestJS with TypeScript and the Fastify adapter for the API and worker codebase.
- Start as a scale-ready modular monolith: stateless API processes, separate worker processes, strict domain boundaries, and later service extraction only when measured load or team ownership justifies it.
- Use Drizzle ORM and Drizzle Kit with reviewed SQL migrations. Enable PostGIS through an explicit migration; automatic schema synchronization is prohibited.
- Use a standard `compose.yaml`, runnable through Podman Desktop or Docker Compose.
- Use PostgreSQL 18 with PostGIS 3.6.
- Prefer Valkey for BullMQ and retain Redis 7.2 only as a compatibility fallback. Phase 2 must run the same queue contract suite against both before claiming interchangeability.
- Use a local-filesystem object-storage adapter and local fake email, SMS, payment, and maps adapters using synthetic data.
- Use Jest for unit, component, API, integration, queue, and adapter tests; Playwright for PWA journeys; and local Maestro CLI for Android journeys.
- Design database access for spatial indexes, query-specific indexes, bounded cursor pagination, batch loading, and measured caching. PostgreSQL remains authoritative for inventory, price, order, and money decisions.

The detailed rationale, boundaries, risks, and verification gates are in [ADR-001](../architecture/ADR-001-internal-development-stack.md).

## Deferred decisions

- Hosting provider and region
- Shared non-production, staging, and production topology
- Managed database, queue, object storage, observability, secrets, backup, restore, deployment, rollback, and disaster recovery
- Production capacity targets and cost envelope
- Store publication and public PWA hosting

## Consequences

Phase 2 may scaffold and test the local foundation. It may not add real provider credentials, purchase services, deploy externally, or claim production readiness. Exact dependency patches and container digests are resolved and recorded during scaffolding, then changed only through reviewed upgrades.
