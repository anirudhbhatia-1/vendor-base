# D-12 — Return to local-only active development

**Status:** APPROVED — LOCAL COMPANY DEVELOPMENT ACTIVE; ONLINE TEST PAUSED  
**Accountable owner:** Project Owner with Engineering Lead  
**Decision date:** 18 August 2026  
**Blocks:** Further online-test provisioning, integration, deployment, credential use, and external-provider activation until a new explicit resume decision  
**Production authority:** None

## Context

The Step 2.6 repository skeleton was used to create four synthetic Cloudflare Pages snapshots and an empty Supabase/PostGIS baseline. Cloudflare R2 was not activated, OCI was not provisioned, and the API, worker, queue, storage, identity, notifications, analytics, and observability adapters were not connected online.

The project owner has directed engineering to return to local company development because the online environment is not workable for the current phase.

## Approved decision

`local`, `test`, and `queue-compat` are the only active execution targets. Normal engineering, verification, synthetic fixtures, fake provider adapters, and repository evidence run locally. No further online-test account setup, resource creation, migration, deployment, or adapter integration is authorized.

The existing Cloudflare Pages snapshots and Supabase baseline are non-authoritative paused resources. They may remain intact to avoid an unrequested destructive action, but they must not be treated as the current application, source of data, release target, backup, or proof of production readiness.

## Consequences

- Root local commands, `.env.example`, loopback services, fake adapters, and deterministic synthetic fixtures remain the working path.
- `infrastructure/online-test/` and `runbooks/online-test/` remain in source control as disabled future reference material.
- Online-test credentials must be removed from developer shells and must not be committed, copied into client bundles, or reused locally.
- Automatic cloud builds, if still enabled externally, create only stale synthetic snapshots and do not change the active-environment decision.
- No cloud resource is deleted by this decision. Deletion requires a separately confirmed inventory, backup/retention decision, and explicit destructive-action approval.
- Resuming online work requires a new explicit decision that inventories existing resources, rotates credentials, confirms ownership and MFA, defines cost ceilings, and re-runs security, migration, recovery, and rollback gates.
