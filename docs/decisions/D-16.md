# D-16 — Azure for Students compute for the online company-test environment

**Recorded:** 17 September 2026
**Status:** Owner-approved test deployment direction; synthetic only; public launch, spending beyond the student credit and real recruitment remain gated
**Basis:** Owner request to deploy the marketplace for company testing at no cost, using the Azure for Students offer available through the GitHub Student Developer Pack.

## Authority and boundaries

D-15 approved the staging adapters and clients and left compute, accounts and deployed availability unassumed. Its provider inventory named OCI Always Free for compute and Cloudflare for the PWAs, both recorded as paused. This decision replaces those two targets and activates nothing else in D-15: every other gate — real people, real money, MSG91/Razorpay/Mappls credentials, production domains, public launch — is unchanged.

Selected targets:

- **Compute:** one Azure Linux VM in Central India (B1ms; B1s within the offer's free hours is the fallback), running rootless `podman compose` from `infrastructure/online-test/compose.yaml`: API, worker, Valkey, Caddy and the customer PWA.
- **Ingress:** Caddy on the VM with Let's Encrypt certificates for two Azure DNS labels on two public IPs. The API and the customer shell are distinct browser origins because the customer BFF's origin check and the API's CORS allowlist are exact.
- **Static shells:** vendor, partner and admin PWAs as static exports on Azure Static Web Apps (Free tier).
- **Database and Auth:** the existing synthetic Supabase development project, unchanged; runtime through its transaction pooler exactly as local development uses it.
- **Images:** built by GitHub Actions from a digest-pinned Node base and stored in GHCR; deployed by digest only.
- **Runtime profile:** `APP_ENV=supabase-production` with `DATA_MODE=synthetic` and `ALLOW_SYNTHETIC_PROVIDERS=synthetic-testing-only` — the profile the marketplace is developed against. The `online-test` profile remains the future staging profile and is not activated by this decision.

## Why Azure rather than OCI

OCI Free Tier requires payment-card verification even when nothing is charged; the runbook recorded that as a stop condition for the account owner. The Azure for Students offer needs no card, grants credit for twelve months and includes free VM hours, so the same synthetic environment can be provisioned without that gate. Cloudflare remains a valid host for static shells; Azure Static Web Apps is chosen so the whole environment sits under one account and one budget alert.

## Options considered

- **Do nothing (local only):** testers need the developer's laptop running; no shared environment. Rejected by the owner's request.
- **Laptop plus a Cloudflare quick tunnel:** free and fast, but the API hostname changes on every restart, which re-bakes every PWA build. Kept as an emergency fallback, not the target.
- **Azure Container Apps:** the worker must stay always-on and consumes credit at roughly the cost of the whole VM by itself. Rejected.
- **Azure VM with compose (selected):** one host, one runbook, all services; the constraint is memory, which a B1ms covers and a B1s covers with swap.

## Required evidence

- `pnpm online-test:verify` and `pnpm lint` pass with the D-16 inventory.
- All three images build locally with podman and the compose stack passes `/health/ready` against the development Supabase project in a laptop rehearsal (Caddy internal CA).
- `pnpm online-test:health` passes against the five deployed URLs with `ONLINE_TEST_EXPECTED_ENVIRONMENT=supabase-production`, then `provider-targets.json` flips `activeEnvironment` to `azure-test` in a follow-up commit.
- A budget alert exists on the subscription before the VM is created.

## Validation-only assumptions

- The fake OTP adapter is the only phone sign-in; the synthetic code is read from the database with `read-synthetic-otp`. Nobody outside the company is invited.
- The filesystem object-storage adapter on a VM volume stands in for Supabase Storage until that adapter's buckets are activated.
- Supabase Free pauses the project after seven idle days; resuming it is an operator action, not an incident.
- Nothing measured on this environment is a capacity or performance result for D-15's staging targets.
